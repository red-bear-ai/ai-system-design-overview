The Power of Caching

LLM inference is expensive and slow. A dedicated semantic cache layer (often Redis + embeddings, separate from the API Gateway) removes duplicate work — a throughput win for the fleet and a latency win for the user.

Cache miss → high latency

~3.8 s total

Cache hit → near-instant

~50 ms total

  • User A: “What is the capital of France?” — computed once, stored in Redis.
  • User B: “Tell me France’s capital” — embedding similarity → cache hit.
  • Bypasses orchestrator, vector DB, and GPU inference.

Dynamic Scaling

GPUs are costly. On a single EC2 box you might resize the instance; on Kubernetes you scale replicas when queue depth or GPU utilization crosses a threshold — restoring throughput without changing per-token inference speed.
